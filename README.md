# Shadow Company

Shadow Company turns a business brief into an evidence-gated decision report and downloadable PDF.

```text
Business brief → editable industry inputs → industry KPI profile
→ constrained scenarios → sourced research → 10-section decision PDF
```

AI organizes inputs, selects approved KPIs for unknown industries, researches current context, and explains results. TypeScript formulas own every calculated value. Missing or AI-suggested company data cannot silently become fact.

## Start

Requirements: Node.js 20+ and npm.

```powershell
npm ci
npm run check
npm start
```

Open [http://localhost:4173](http://localhost:4173) and choose **Create my business report**.

## Better inputs and scenario review

- Paste a full brief or import a two-column CSV such as `metric,value` to populate recognised operating metrics.
- Add geography, reporting currency, and the date through which inputs are current. Geography is included in live-research queries.
- Download the model inputs and scenario outputs as CSV alongside the decision PDF.
- Scenario cards distinguish a **candidate experiment** from a validated recommendation; a visual highlight never overrides the evidence gate.

## Deployment safeguards

The server listens on `127.0.0.1` by default. Set `HOST` deliberately when deploying behind a reverse proxy.

For protected deployments, set `APP_API_KEY` and have the reverse proxy or trusted client send it as a Bearer token for mutation endpoints. The server also applies a restrictive content-security policy, per-route request limits, a two-report concurrency limit (configurable with `MAX_CONCURRENT_REPORTS`), bounded in-memory report caching (`MAX_CACHED_REPORTS`), and structured operational events without logging business-brief content.

```powershell
$env:HOST="0.0.0.0"
$env:APP_API_KEY="replace-with-a-long-random-secret"
npm start
```

Do not expose an API key in public browser JavaScript. Put authentication at a reverse proxy or use a server-side trusted client.

## Private report archive

To review PDFs generated by public users, enable the optional private Supabase archive and administrator report viewer. It stores PDFs outside the server's temporary memory and exposes them only through a password-protected `/admin/reports` page.

See [Supabase report archive setup](docs/supabase-setup.md) for the SQL, private bucket, and deployment environment variables.

## Provider modes

Use the Codex / ChatGPT account authenticated on the computer:

```powershell
codex login
$env:AI_PROVIDER="codex"
npm start
```

Codex organizes the brief and attempts focused live industry research. Research has a hard timeout and never blocks the calculated report indefinitely. Account use is subject to the Codex usage included with the signed-in ChatGPT plan.

For a public deployment and the most reliable hosted search workflow, use the OpenAI Responses API:

```powershell
$env:AI_PROVIDER="openai"
$env:OPENAI_API_KEY="your-server-side-key"
npm start
```

The API path uses the hosted `web_search` tool and preserves returned source URLs as clickable citations.

Run without an external provider:

```powershell
$env:AI_PROVIDER="local"
npm start
```

Local mode still provides deterministic industry KPI profiles and calculations, but does not add current web research.

## Industry KPI profiles

Built-in profiles cover:

- Hotels and lodging: Occupancy, ADR, RevPAR, Net RevPAR, contribution per available room.
- SaaS and subscriptions: MRR, ARR, gross margin, churn, NRR, LTV:CAC.
- AI subscriptions: MRR, direct AI cost per paid account, AI cost share, loss-making account share, failed-task rate, churn, NRR, and CAC payback.
- Physical products and e-commerce: AOV, contribution per unit, gross margin, inventory turnover, repeat purchase.
- Professional services: billable utilization, revenue per employee, project margin, backlog coverage.
- Restaurants: average check, table turnover, food cost, labor cost.
- Manufacturing: capacity utilization, yield, throughput, contribution per unit.
- Marketplaces: GMV, take rate, liquidity, buyer retention.
- Healthcare operations: provider utilization, revenue per visit, no-show rate, patient retention.
- Income-producing real estate: occupancy, rent per area, NOI, capitalization rate.
- Logistics and field operations: delivery throughput, fleet or route utilization, contribution per delivery, repeat retention.
- Membership, fitness, and education services: retention, class or seat utilization, revenue and contribution per attendance.

For an unrecognized industry, AI may select up to six KPIs from the approved formula library. It cannot create or calculate an unrestricted formula. Required inputs must be mapped and reviewed first.

## Hotel decision model

The hotel adapter uses properties, rooms per property, analysis days, occupancy, ADR, length of stay, cancellations, direct-booking share, third-party commission, variable room cost, fixed cost, and price elasticity.

It enforces:

```text
occupied room-nights ≤ properties × rooms × days
```

The pricing analysis compares a 12% rate change at 0%, −5%, −10%, −15%, and −20% volume response and calculates the operating-contribution break-even decline. It does not call simplified contribution “ending cash,” EBITDA, or a cash-flow forecast. When critical inputs remain AI-suggested, the report says **insufficient evidence** and recommends an experiment rather than a winning scenario.

## AI subscription decision model

AI software reports use a dedicated scaling and unit-economics model. Editable inputs include the defined AI task unit, paid accounts, typical and high-volume usage, churn, paid conversion, payment cost, refunds, failed or retried tasks, CAC, target gross margin, price elasticity, included usage, and overage price.

The adapter compares neutral flat-plan, allowance, price-plus-overage, and model-routing cases. It calculates economics for light, typical, heavy, and extreme usage cohorts; shows monthly revenue, AI cost, gross margin, and contribution from 100 to 5,000 paid accounts; tests price-volume retention and churn; and separates simple revenue break-even from operating-contribution break-even. Missing usage reconciliation, observed churn, or price response blocks a permanent pricing recommendation.

## Report structure

The PDF is intentionally limited to roughly 10–15 pages:

1. Decision summary
2. Evidence status
3. Industry economics and KPIs
4. Scenario comparison
5. Elasticity and break-even analysis
6. Market, customer, and competitor context
7. Risks and decision controls
8. Recommended experiment
9. Action plan
10. Methodology, limitations, and clickable sources

## Evidence rules

- Calculated values come only from approved formulas.
- AI-suggested inputs remain visibly low-confidence and editable.
- Research findings must map to returned source URLs.
- External benchmarks are context, not company performance.
- Research cannot overwrite company inputs.
- Unsupported recommendations are blocked.
- Market size, competitor pricing, legal claims, and citations cannot be invented.

## Universal quality gate

Every report is scored out of 100 using weighted business clarity, customer understanding, market and trend evidence, competitor analysis, revenue-model clarity, cost credibility, financial accuracy, scenario realism, risk analysis, recommendation quality, actionability, and readability.

- 90–100: decision-ready.
- 75–89: strong with limited gaps.
- 60–74: useful internal draft.
- 40–59: weak; major revision required.
- Below 40: not suitable for business decisions.

Critical failures are non-compensatory. Missing industry mechanics, unverified critical inputs, or absent sourced research can cap readiness even when presentation and risk wording are strong. The report also runs a ten-question normal-reader comprehension test.

## Evidence confidence scaling

The evidence ledger separately lists user-provided inputs, AI suggestions with confidence labels, and linked external sources. It produces one of three evidence ratings:

- **Directional:** short report, rounded numbers, cautious language, and no winning scenario.
- **Partially Validated:** normal report, standard precision, and only a provisional direction.
- **Evidence-Based:** full report, specific precision, and a clear reasoned recommendation is allowed.

The corresponding report-header statuses are **Directional Scenario**, **Validated Estimate**, and **Confirmed Forecast**. This policy is enforced after narrative generation, so neither an AI writer nor the generic simulation can bypass it.

## Main implementation

- `src/simulation/engine.ts`: general seeded scenario engine.
- `src/web/briefCompiler.ts`: long-form brief organizer and editable industry defaults.
- `src/report/kpiRegistry.ts`: KPI profiles and approved formula library.
- `src/report/industryAnalysis.ts`: hotel capacity economics plus AI subscription scaling, cohorts, elasticity, and technical-cost sensitivity.
- `src/report/businessReport.ts`: evidence contract and recommendation gating.
- `src/report/reportConfidence.ts`: evidence rating, status, length, precision, and winner-language enforcement.
- `src/report/pdf.ts`: short, pagination-safe PDF renderer.
- `scripts/serve.mjs`: providers, web research, report generation, and PDF endpoints.
- `web/`: input review, report preview, citations, and download.
